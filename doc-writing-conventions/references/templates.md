# 文档骨架与专项规范入口

本文件供撰写 skill 与代理指令文件的人和模型使用，提供内容组织骨架，不代替 `SKILL.md` 的适用范围与规则。按用途选择骨架，替换占位项并删除不需要的章节；标题数量与开篇句数不固定。全文分为 skill 骨架、代理指令文件骨架、ADR 入口与填写检查。

## 一、skill 骨架

先按 `SKILL.md` 第一节判断文档类型，再应用 R1～R6；非日志记录类文档还必须遵守 R7。references 文件同样需要独立分类，禁止将现状说明与历史日志混写。

```markdown
---
name: <kebab-case，与目录名一致>
description: <做什么、何时加载、触发场景或关键词。>
---

# <skill 名>

<交代给谁用、解决什么问题、读完能做什么；内容较多时说明全文结构。>

## 适用范围

适用：
- <触发场景，含用户可能使用的关键词>

不适用：
- <相邻任务与对应做法或专项 skill>

## 原则

- <有明确对象与条件的约束>

## 流程

1. **<动作>**：<输入依据、执行动作与产出>
2. **<动作>**：<输入依据、执行动作与产出>

## 自检

- [ ] <能够根据产出判断的验收项>
```

主文件保留适用范围、关键约束、流程与验收入口。仅在执行时需要的长模板、示例和解释放入 `references/<主题>.md`，在使用处给出相对路径及读取条件；禁止为凑篇幅阈值机械拆分。

其他 skill 已覆盖的专项流程只给出读取入口，禁止复制第二套规则。`description` 用于决定何时加载，不重复完整正文。

## 二、代理指令文件骨架

开篇交代约束对象与生效范围，随后直接给出可执行要求。以下章节按项目实际需要取用，不要求固定数量或标题形式。

```markdown
# <项目名>：代理指令

<本文件约束谁，在哪些工作中生效。>

## 铁律

- 禁止 <具体行为与对象>。
- 当 <明确条件> 时，必须 <动作>。
- 当 <无法确认的事项> 影响执行时，必须先向用户确认。

## 规则冲突处理

<列明已经确认的优先级；没有明确裁决依据时，先向用户确认。>

## 需要查阅的资料

- 当 <触发条件> 时，读取 `<相对路径或 skill 名>`，执行 <对应规则或流程>。

## 项目约定

<确需模型执行、且未由工具链或专项规范覆盖的约定。>
```

要求必须有具体对象与动作；理由用于解释容易误用的边界，不要求每条都重复代价。禁止写入开发推进记录、已作废约束的历史或与任务无关的教程；历史记录必须放入独立的日志记录类文档。

## 三、ADR 专项入口

ADR 属于日志记录类文档，记录技术决策发生时的前因后果，不受 R7 约束；禁止混入用于指导当前使用的现状说明，需要关联时链接独立文档。

创建、更新、取代或维护 ADR 时，必须加载并读取 skill `adr-writing`，按其要求核实项目模板、目录与索引。格式、元数据、章节标题、状态流转和历史维护由该 skill 负责，本文件不提供另一套 ADR 模板或维护规则。项目资料缺失或规则冲突时，必须先确认，禁止自行补造模板或历史决策。

正文按本规范消除歧义、冗余与无依据的表述；禁止为了满足通用开篇或标题形式而重排 ADR 专项模板。

## 四、填写检查

| 检查对象 | 判据 |
| --- | --- |
| 文档类型 | 用途明确；现状说明与历史日志分开存放，禁止混写 |
| 开篇 | 符合文档类型，让读者知道用途；不强制固定句数 |
| 标题 | 准确概括内容，同级粒度一致；不强制名词短语 |
| 要求 | 具体对象、动作与适用条件明确，硬性要求使用“必须”或“禁止” |
| 示例 | 说明真实易错边界，不为成对出现而重复正文 |
| 指代 | 能对应到唯一对象，不机械禁止某个词 |
| 数值 | 有依据；没有真实阈值时用明确条件或可判定结果 |
| 路径与入口 | 路径可定位，说明何时读取；专项流程不重复维护 |
| 现状更新 | 按代码与已确认事实更新，清理失效描述，不记录 AI 修改过程；未确认偏差先询问 |
| 历史维护 | 保留当时事实，按专项规范维护；不为呈现当前状态而改写历史 |

写完后必须执行 `SKILL.md` 第五节中适用的自检项；修改规则时同步核对主文件与 references，禁止保留冲突要求。
