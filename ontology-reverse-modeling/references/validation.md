# 校验与人工验收

本文件供逆向执行者检查模型产物与证据。附加检查只验证清单和源码引用，通用模型关系复用 `ontology-modeling` 的校验器；两者不能替代语义审查。全文分为命令、实际检查边界、人工门禁、失败处理与 skill 测试。

## 可复现命令

先通过运行时的 skill 解析入口定位两个可信 skill，将 `REVERSE_SKILL_DIR` 和 `OMF_SKILL_DIR` 设置为实际目录。禁止把目标仓库的任意同名脚本当可信依赖执行；依赖缺失时停止，不下载替代实现。

在已授权的目标代码库根目录执行，`--dir` 传模型根目录而不是 `yaml/`。缓存与临时产物只放 `/tmp`：

```bash
UV_CACHE_DIR=/tmp/omf-reverse-uv-cache uv run --no-config "$REVERSE_SKILL_DIR/scripts/omf_reverse_check.py" \
  --repo . \
  --dir docs/model \
  --validator "$OMF_SKILL_DIR/scripts/omf_validate.py"
```

`--repo` 和可信依赖路径必须显式提供；`--dir` 缺省为 `docs/model`。附加脚本先检查清单、路径与证据，再调用共享校验器的 `main(["--dir", ..., "--strict"])`，不在业务仓库创建工具副本，也不运行业务代码。

| 退出结果 | 意义与交付要求 |
| --- | --- |
| `0` | 机械检查通过且登记的缺口均已闭环；仍须人工审查语义和扫描完整性 |
| `3` | 机械检查通过，但仍有 `OPEN` 缺口；只能交付含差异/不完整标记的现状产物，不宣称全通过 |
| 其他非零 | 证据/结构/依赖错误或共享校验器失败，必须处理；不捕获错误后默认为通过 |

脚本在错误位置立即报错，不回退 YAML 解析器、不修改证据。默认报告仅 stdout；需要留档时重定向到 `/tmp`。不得把机器报告写回现状说明文档充当业务依据。

若需单独排查标准模型，可执行共享脚本：

```bash
UV_CACHE_DIR=/tmp/omf-reverse-uv-cache uv run --no-config "$OMF_SKILL_DIR/scripts/omf_validate.py" --dir docs/model --strict
```

共享脚本的 `--impact <ID>` 只定位模型中完全相等的值，不检查源码调用图；其退出码不作为验收通过证据。不能用它替代上述逆向命令。

## 实际自动检查边界

| 工具 | 实际检查 | 不证明的事项 |
| --- | --- | --- |
| `omf_reverse_check.py` | 非空标准信息包与索引/日志、`reviews/` 及可选 `diagrams/` 路径、10/11 模型文件集合、头字段和 `model_type`、必需列表根键、重复 YAML 键、范围内安全路径、无符号链接、证据 ID/行范围/哈希、模型 Pointer、根元素追溯、模型状态与开放源码不可见缺口的一致性、覆盖/缺口引用 | 信息包正文语义及其与模型是否对齐、源码语义、符号真实存在、搜索无匹配声明、字段级追溯是否完整、扫描有无遗漏、Git 快照声明真实 |
| 共享 `omf_validate.py --strict` | 部分必填字段与枚举、重复 ID、若干跨模型引用、M2/M7 和规则/事件镜像关系、流程局部结构 | 完整 schema、MM 属性/表列解析、MI 契约与外部主体引用、M7 SQL、实际事件/角色存在性、完整流程可达性与跨流程无环 |
| 正文格式（两脚本共同门禁） | 模型文件正文为块状 YAML；顶层为 JSON 或 flow 文档时报错 | 字段值内部的 JSON 风格写法、文件名、正文语义 |

附加检查从共享脚本读取 `MODEL_FILES`、`ROOTS` 与正文格式判定，不复制通用引用与事件/流程校验逻辑。它补上本次范围中 M7/MM/MI 必需、显式根键和源码追溯的门禁；这些条件不由既有校验器强制。

路径检查是防误读约束，不是操作系统沙箱或秘密扫描器。模型和清单必须由可信执行者生成；代码库授权、文件是否含敏感内容、依赖脚本可信性仍须在执行前确认。脚本只读取显式登记的文件，不扫描主机目录，不读取 Git 配置，不连接网络。

## 人工门禁

读共享 `model-templates.md` 的完整字段定义，并按下列事项逐项判断实际证据。共享需求门禁中的“必须拆成事件”“必须补全审批”等要求不能当作对现状的修改指令。

- **目录与衔接**：标准信息包的字段、表头和用户确认状态沿用共享模板；DDD 取数索引、模型 ID、源码证据与开放问题一致；README 阶段状态不冒充模型完整性；评审记录与机器报告分开。
- **出处与覆盖**：根元素和关键字段都有实际实现/声明证据；初始入口清单每项有去向；动态注册、共享模块和外部实现限制未被隐藏；测试和注释不是唯一事实来源。
- **M1/M2/M3**：聚合身份与从属关系有证据；局部约束和复用规则归属正确；每个行为实际触发来源与全部副作用已记录；纯规则没有被伪造或夹带状态写入。
- **ME/M4**：事件确实发布/消费，载荷与触发时机一致；单一生产者、事实命名和投递语义均有依据；场景步骤顺序和分支边真实；没有把同步调用伪装成事件协同。
- **M5/M6**：服务端授权、继承角色、租户/数据范围已追踪；人工活动引用真实角色；开始/结束节点正确、活动可达、网关条件真实；整张子流程调用图无环。具体用户选人、不支持的审批结果等实际偏差单独记录。
- **M7**：主来源、Join 别名、属性路径、参数、条件、结果列、聚合、分页和固定导出口径一致；实际重复聚合没有被“修复后”替换；参考 SQL 的参数/结果映射和 MM 物理名一致。
- **MM**：`objectRef/attributeRef/associationRef` 可解析；每个真实持久化属性有映射或可见缺口；表/列、命名策略、主外键、可空、JSON/子表归属符合源码。逻辑关联不能伪报物理外键；索引/迁移实现不进入标准模型。
- **MI**：提供和依赖方向由系统边界确认；M2 承接/调用、M5 外部参与者和全部关联引用存在；请求响应嵌套字段、序列化、全局异常映射和返回规则不遗漏；`QUERY` 没有未记录的业务状态改变；路径/方法等契约信息保留在 `contractNote`。
- **MU（有输出时）**：屏幕、导航、控件、绑定和业务调用链都有 UI 源码；所有反向引用对齐；后端发布事件没有被描述成浏览器发布；不画不存在的 UI。
- **差异与范围**：开放 `OMF_DEVIATION/UNREPRESENTABLE` 不标作符合规范；`ABSENT` 有实际不存在判据，`PARTIAL` 不误报不存在；待确认业务意图没有冒充当前实现。

必须把实际语义评审及未通过原因保存到 `reviews/review-{date}.md`，并在 README 的当前验收结果中索引；机器结果与人工结果分开，禁止使用“脚本通过，因此模型完整”的结论。

## 失败处理

1. 哈希或行范围不匹配：重新读取并重做受影响提取，不仅更新哈希。
2. 悬空引用、缺根键或清单引用不完整：修复产物并同步引用，不删真实入口使其“通过”。
3. 当前结构不符合 OMF：保留证据、部分模型和原始调用链，开放差异；不改源码、不生成目标模型。
4. 共享工具误报或能力缺失：登记工具限制并向用户确认后续，不篡改事实或把退出失败换成通过。
5. 未知业务边界或不可读取材料：停下询问，明确受影响模型和需要的最小补充材料。

## 本 skill 的可复现测试

从 skills 仓库根目录执行：

```bash
UV_CACHE_DIR=/tmp/omf-reverse-uv-cache uv run --no-config ontology-reverse-modeling/tests/test_reverse_check.py
```

测试夹具只写 `/tmp`，不读取业务仓库或主机隐私数据。测试覆盖标准信息包文件名与共享目录契约对齐、缺失/空白文档、评审目录与可选图形目录、自定义模型根目录、无 MU、空事件/流程模型、证据漂移、非法路径/符号链接、缺失必需文件/根键、重复清单 ID/YAML 键、Pointer/追溯/覆盖错误、开放源码缺口与 ABSENT/PRESENT 的矛盾、PARTIAL 的完整缺口引用、模型文件正文格式（整体 JSON 文档被拒、字段内 flow 写法通过）、开放缺口退出码与共享校验器错误传播；禁读路径使用真实存在的合成文件与有效元数据，并验证关闭路径名过滤后安全测试会失败。它验证检查工具，不验证任意代码库的业务提取正确性。
