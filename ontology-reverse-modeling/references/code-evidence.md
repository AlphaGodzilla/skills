# 按模型取证与源码扫描

本文件供源码逆向执行者建立入口清单并寻找每个模型所需的实现证据。它不规定目标系统应该采用什么架构，也不提供跨语言业务语义的自动解析器。全文分为安全扫描、调用链取证、逐模型判据和完整性检查。

## 安全扫描

1. 先核对范围卡，只列已授权目录的文件名。排除 `.git/`、依赖包、构建产物、生成代码、模型输出、真实日志和数据文件；生成代码确需解释协议时先确认其来源和生成输入，不把它当业务实现。
2. 从源码/声明文件中挑选安全路径建立读取白名单，然后仅在白名单文件内定位符号。禁止从仓库根目录执行无排除的递归全文搜索，避免意外读到 `.env`、证书、凭证和生产配置。
3. 读取 Java/Kotlin、C#、Python、Go、TypeScript、Ruby 等源码，以及确属项目实现输入的 ORM、Mapper、SQL 迁移、Proto、GraphQL、BPMN 声明。SQL 迁移只能证明仓库声明的结构，不能证明生产库已应用该迁移。
4. 配置型业务语义只使用已确认不含凭证的声明；需要真实账户、数据库连接或运行时密钥才能验证时停止询问，不通过连接真实服务补证。
5. 文件内意外出现敏感值时停止扩散，不将值复制到证据、模型或报告；使用者必须提供不含敏感内容的安全来源。字段名与认证类型可以建模，真实凭证和具体账户不得入模。

源码工具、AST（抽象语法树）、调用图或项目已有索引只能帮助定位，不自动证明业务边界。必须读取定义和调用方；动态调用、插件和条件注册无法解析时登记缺口。

## 沿执行链取证

逐个入口追踪以下节点，并保留分支而非只有成功链：

`路由/命令/调度/消息入口 → 全局与局部鉴权 → 参数校验 → 应用与领域方法 → 持久化/外部副作用 → 事件发布 → 返回及异常处理`

- 上行核对触发来源、实际可达性、角色与数据隔离条件。
- 下行核对间接调用、读写对象、事务、状态迁移、生产者、订阅者和外部请求。
- 横向核对共享校验器、ORM 转换器、全局异常映射、重试/幂等逻辑与同名方法的不同实现。
- 注解、路由和方法存在不等于在当前构建中启用；条件编译、注册开关和选用实现缺失时暂停结论。
- 测试用于查找边界、异常和意图；没有运行的测试不能证明行为通过，测试与源码不一致时询问而不是采用测试期望覆盖源码。

## 逐模型取证判据

### M1：业务对象不是表的翻译

证据：业务类/类型、构造器、聚合方法、持久化访问、删除路径、状态迁移和引用方式。验证对象的独立身份、访问入口、生命周期与不变性后再确定聚合边界。

- 一张表不等于一个聚合，DTO/请求对象也不自动成为聚合。
- 子实体需证明从属访问和生命周期；外键、同事务或级联注解各自只是证据，不能单独证明“同生共死”。
- 属性类型、空值、默认值、枚举、字典 code 来自实际声明与执行路径；可更新的字典项不能凭常量表误作固定枚举。
- 必填/唯一声明要区分仅入口校验、领域校验和数据库约束。约束只在部分入口生效时不得写成无条件对象不变性；记录作用范围与缺口。
- 根据读取范围分层：内置约束 → 单属性 `refRules` → 同聚合 `invariants` → 跨对象/复用 M3。
- 业务名称或聚合边界无法唯一确定时询问，不给未经确认的中文业务解释。

### M2：实际行为与全部副作用

证据：用例处理器、应用服务、聚合方法、任务/消息处理器及其调用方。

- 按实际改变状态还是只读选择 `COMMAND / QUERY / EVENT_HANDLER`，不凭 GET、POST 或方法名判断。
- 前置条件取实际状态/授权/校验路径；后置条件取所有成功、失败、补偿分支的业务变化，禁止遗漏间接跨对象写入。
- 同一行为的调用来源需全部核对；`triggerType` 表示触发来源，不是当前方法是否调用了外部服务。
- `producedEvents` 只引用实际发布且在 ME 定义的事件；未发布时留空。
- 不把“可从方法中概念拆出”的步骤描述成已实现的独立处理器。无法表示的同步编排保留原始调用链并记缺口。
- 单聚合简单查询可不绑定 M7；绑定 M7 时严格一对一，不能为满足绑定而复制查询入口。

### M3：业务决策与对象局部约束分开

证据：Policy/Specification、共享校验和计算逻辑、规则文件、条件分支、事件决策处理器及全部调用点。

- 提取真实输入、读取对象、表达式、输出类型、版本和复用关系，保留比较运算、阈值、币种、舍入、时区与空值分支。
- HTTP 格式校验、数据库约束与单字段检查不批量塞进 M3；纯查询条件归 M7。
- `EVENT_DRIVEN` 必须有实际订阅证据；`triggeredBehaviors` 必须可追踪到实际调用。
- 副作用和日志等实现细节需与业务判断区分；不能保证纯判断时记录问题，不臆造一个新的纯规则组件。

### ME：声明、发布和消费三处对齐

证据：事件/载荷类型、实际 publish/send 调用、监听注册与处理代码；消息桥接还需追到序列化和分发声明。

- UI 点击、技术日志、异常对象、消息 topic 名不自动等于领域事实事件。
- 只有事件类没有发布代码，不能宣称会发生；只有发布没有消费，也不能补造消费者。
- 消费者位于另一个仓库时，区分本仓库已证明的发送契约和不可见的消费实现，不宣称不存在消费者。
- 核对生产者唯一性、成功/事务提交后的发布时机、载荷字段来源、消费条件、重试与幂等路径。
- 不把消息系统的常见默认配置当投递保证；配置不可见时省略尚无证据的可选信息并记缺口，禁止擅填 `AT_LEAST_ONCE` 或 `EXACTLY_ONCE`。
- 同步进程内事件总线也可以形成事件关系，`SYNC/ASYNC` 必须按源码；“事件解耦”不自动等于异步队列。

### M4：真实事件协同，不是普通调用链

证据：ME 已证明的 `生产者 → 事实事件 → 规则/行为消费者 → 不同聚合变化`。

- 必须存在跨对象影响和事件衔接；同步服务串调用不能直接转换为事件步骤。
- 只使用 `BEHAVIOR_CALL / EVENT_EMIT / RULE_EVALUATE`，角色任务、网关和审批分支归 M6。
- 有条件的消费者按真实判断建立规则关系；无条件消费不得为了图形对称补造规则。
- 不存在事件协同就保留 `event_scenarios: []`；框架希望事件化的同步代码进入差异清单，不进入假想场景。

### M5：类型与授权，不读取真实账户

证据：鉴权中间件、过滤器/注解、RBAC（基于角色的访问控制）策略、ABAC（基于属性的访问控制）条件、数据范围过滤、角色常量及安全的声明数据。

- 构建主体类别、角色和权限，不读取用户表数据、个人账户文件、token 或生产角色分配。
- 前端隐藏按钮不证明后端授权；分别查真实服务端强制路径和 UI 条件。
- 没有明确授权检查不自动意味着 `ALL` 或匿名访问，必须追踪全局安全链。
- 核对租户、所有者、部门、软删除、对象级鉴权；继承权限与数据范围按实际条件表达。
- 外部参与者必须有已证实的系统边界；认证类型可记录，密钥内容禁止记录。

### M6：业务流程图与方法流程图区分

证据：BPMN/工作流状态机、流程实例和任务模型、审批处理、网关、调度与流程服务注册。代码驱动的跨阶段业务编排也可提取，前提是业务阶段与转移有明确实现证据。

- 普通方法顺序、状态枚举或用户可能操作的功能列表不自动形成端到端流程。
- 只记录实际支持的通过、驳回、退回、撤回、超时及补偿；未实现的路径登记缺口，不补造。
- 人工活动使用已证实的 M5 `roleId`；实际按具体用户选人而无法还原角色时记录规范偏差。
- 检查唯一开始、合法结束、分支目标、可达性、子流程调用图以及事件等待超时。
- 流程调用 M4 从已发生事件衔接，禁止重复执行上游行为。没有流程/审批时允许空集合。

### M7：真实查询和报表口径

证据：Repository/Mapper/SQL、查询构造器、Projection、聚合管线、报表/导出服务及绑定入口。

- 跨对象查询、分组统计和固定导出才建立正式 M7；简单单聚合详情/列表可只在 M2。
- 保留实际 Join、Where、可选参数、空值、预聚合、Group By/Having、排序、分页、结果列和导出格式。
- 读权限归 M2/M5，不能从查询 SQL 中删除租户/部门过滤；区分安全过滤与业务查询条件，并保持语义一致。
- 多个一对多来源可能造成重复累计，发现现有错误只记录实际表达式与偏差，不自动修复。
- `referenceSql` 仅记录可证明的 SQL/方言和参数映射；ORM 动态查询无法确证物理 SQL 时不编造“实际 SQL”。
- NoSQL 查询、搜索或远程读模型不能假装是关系 SQL；OMF 无法表达的部分保留原始语义并记表示缺口。

### MM：真实物理映射，不猜命名策略

证据：ORM 映射、Mapper、SQL、结构迁移、字段转换器、继承/命名策略和实际序列化代码。

- 核对 schema/表名、列名、类型、主外键、可空、默认值、子表归属、嵌入对象和 JSON 列。
- 语言类型不证明数据库列类型；逻辑 ID 引用不证明数据库有物理外键约束。
- ORM 默认命名需找到实际策略；只见实体名不能猜物理表名。迁移和当前 ORM 冲突时保留双方证据并询问。
- `attributeRef` 指向 M1 真实路径；技术审计/租户/版本列不必硬造 M1 业务属性，但要说明其非业务映射性质。
- 一对象多表按实际 MASTER/DETAIL/EXT 等结构；索引、分区、迁移脚本不进入 MM。
- 内存、文件或文档存储不虚构关系表。MM 范围内无表映射时为空；确有持久化但标准无法表达时登记 `UNREPRESENTABLE`，不能误标未持久化。

### MI：提供与依赖两侧契约

证据：服务端路由/协议处理器、请求响应类型及序列化、全局异常/响应包装、客户端调用、协议声明和安全链。

- 先确认系统边界：前后端同系统内部调用、库函数和技术健康检查不自动属于外部业务接口；所有入口先在覆盖清单交代去向。
- `PROVIDED` 追踪真实处理行为；`DEPENDENT` 追踪真实调用者与 M5 外部参与者。不存在某一方向时不为“两类齐全”补造接口。
- 原样保持请求/响应字段名称、嵌套对象/列表、枚举、可选性与转换规则；和 M1/M7 口径不同时记录映射，不把字段改名成理想名称。
- `returnRule` 包括已实现的无记录、参数错误、权限错误、冲突、外部失败和超时映射；查全局处理器后再确定返回形式。
- 协议方法、路径、状态码等原文无独立字段的契约信息，可使用 `contractNote` 表达并附独立字段追溯；禁止自造 `endpoint` 等标准外字段。
- `relatedBehaviorRef` 等关联字段是数组，名称不带复数 `Refs`；`relatedExternalEntityRef` 指向 M5 `actorId`。
- MQ/通知契约关联 ME，不重复定义其领域载荷；认证、超时、幂等只有证据才填写。

### MU（明确纳入时）：UI 入口到业务引用

证据：页面/路由、组件/表单、事件处理器、导航、调用 API 客户端与数据绑定。

- UI `callChain` 是业务调用链的追溯表达，不表示浏览器直接发布了由后端行为产生的事件。
- 查询/表单校验/导航按实际链路，不能凭后端有行为就假设某按钮调用它。
- 控件级必填与后端约束、UI 隐藏与后端权限不一致时如实记录。
- 跨仓库前端缺失时不补造屏幕；只画布局不算完成 MU，视觉主题不进入模型。

## 完整性检查

完成提取后与最初入口清单对账，不能只对已有模型做自检。至少包括路由/命令/定时任务、消息处理、业务对象、决策/权限、流程、查询/导出、持久化对象和两侧接口；每项均需模型引用、缺口引用或明确的排除原因。

未访问的共享模块、未知调用目标和未解析的动态注册必须作为可见缺口，不得标作已排除或无对应功能。一个搜索无匹配不是“不存在”的充分证据；不存在判据还需说明实际检查的目录、注册机制和可能的仓库外实现。
