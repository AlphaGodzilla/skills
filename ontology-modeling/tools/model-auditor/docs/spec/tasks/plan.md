# 浏览器多标签共享审计实现计划

本计划将已确认的[功能设计](../../design/browser-tabs.md)和[架构决策](../../adr/0001-adopt-shared-worker-workspaces.md)落实为可分别验证的改动。[任务清单](todo.md)记录验收状态，不代替源码或使用说明。

## 范围与依赖

依赖顺序：导航身份与工作区核心 → worker 传输及只读服务 → 浏览器导航与审阅交互 → 打包与跨页验收。只允许一名代码写入者，审查与环境验证可只读并行。所有临时构建、浏览器 profile、测试输出与报告放在 `/tmp`；不访问个人配置、账户或凭证。

| 检查点 | 交付能力 | 证据 |
| --- | --- | --- |
| 工作区核心 | 稳定定义键、版本化路由、字段 CAS、事务性导入、屏障及快照导出水位 | 先新增失败测试，再验证核心与现有 28 项测试 |
| 共享运行时 | 命名 worker 的 CREATE/JOIN、接入快照、有界消息窗口、loopback 静态白名单、同版本产物 | 端口集成、服务安全与构建完整性测试 |
| 页面交互 | 全部内容导航为原生链接、有界视图查询、阅读位置隔离、草稿冲突和导出确认 | 打包 DOM 集成与多客户端协议回归 |
| 发布验证 | 单页模式回归、共享模式跨页流程、正确使用说明 | 全套测试、真实浏览器结果或明确阻塞、独立审查 |

## 验证入口

从工具目录执行 `npm test`，包含现有核心与打包 HTML 的 DOM 测试。新增测试按职责加入 `*.test.mjs`，独立命令记入 package scripts。现有构建使用 `node build.mjs start`、顺序 `part N`、`finish`；新增 worker／清单必须沿用分批暂存与整套发布，不能直接写入超大 HTML 或发布半套资源。

跨页运行和测试需要只读本地服务；`node serve.mjs` 是只读服务入口；干净分发须包含清单及其所指的当前 HTML/worker bundle，不依赖 node_modules 或历史目录。测试浏览器必须使用 `/tmp` 中的新 profile，不复用用户已有浏览器数据；无法执行真实浏览器检查时不以 jsdom 或 mock 替代发布验收结论。

## 不变量

- 普通点击当前页导航；修饰点击交给浏览器，原页不导航。`file://` 仍为明确的单页模式。
- 模型与权威审阅只在浏览器工作区内存；服务只提供已验证静态资源，不处理业务请求。
- 不向新页克隆整套模型／索引；列表、原文和上下文按现有分页返回。
- JOIN 不创建伪恢复工作区；实例、数据集、字段修订、请求序号和确认水位不可混用。
- 冲突、失联、超时和后台冻结不能导致无提示覆盖、自动批准破坏性操作或无限消息积压。
- 源 YAML 只读，表达式永不执行；既有导入限制、检查范围和来源指纹保持有效。
