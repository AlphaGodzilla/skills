# OMF 模型审计器

供程序员审查 ontology-modeling 输出的 YAML。模型只读，人工结论和备注保存在浏览器易失内存中；不上传模型，不提供持久化或审阅 JSON 恢复导入。

## 启动与分发

| 模式 | 启动 | 状态所有者 |
| --- | --- | --- |
| 多标签共享 | 在本目录运行 `node serve.mjs`，打开输出的实际地址 | 同一 origin、浏览器 profile 和存活 SharedWorker 中的工作区 |
| 独立单页 | 直接打开 `omf-auditor.html`，无需 Node 或服务器 | 本页面的显式本地适配器；复用相同核心和有界查询 |

共享服务需要 **Node.js 22+**，只依赖 Node 内置模块，使用已打包资源，不需要 `npm ci`。服务只绑定 `127.0.0.1` 的动态端口，不接受上传、业务请求或模型目录访问。所有标签页须保留同一 scheme、host、port 和页面路径；不要混用 `localhost` 与 IP。

完整的共享分发必须包含：

- `serve.mjs`、根目录 `omf-auditor.html`、`omf-auditor-manifest.json`；
- 清单指向的 `builds/<buildId>/omf-auditor.html` 和 `builds/<buildId>/workspace-worker.js`。

不需要 `node_modules`、缓存或历史构建目录。不能只复制根 HTML 就宣称具备共享服务；单个 HTML 只承诺独立单页模式。服务启动时验证整套资源的 buildId、大小、SHA-256 和 CSP，并固定为内存中的同一版本；资源损坏时拒绝启动，不混合热更新。

浏览器需要 MessageChannel、Web Crypto 和 structuredClone；共享模式另需 SharedWorker。SharedWorker 不可用或加载失败时显示错误，不自动创建各自独立的副本。**macOS Chrome / Safari 的真实浏览器发布验收尚未完成**，自动测试不是浏览器支持声明。

## 审查与导航

1. 加载合同示例，或通过文件选择、目录选择、拖放导入 YAML。普通文件选择不能区分来自不同目录的同名文件；目录导入保留相对路径。
2. 左侧按名称、ID、文件名或模型编号搜索、筛选。对象聚合卡片可就地展开；场景步骤和流程活动保留声明顺序及关联定义。
3. 工作台、问题清单、权限矩阵、导入文件，以及定义的审计摘要、全部字段、引用关系都使用真实链接。普通左键只导航本页；Cmd / Ctrl / Shift / Alt / 中键及右键新页交给浏览器，不强制激活新标签。
4. 从内容链接打开的新页直接接入同一工作区，不需要重选文件；单独打开不带工作区地址的首页创建新工作区。工作区链接含接入凭证，不应对外分享。
5. 原文链接普通点击保留当前定义和视图；其新页地址选择原文所属定义及准确字段。面板分别标明原文所属定义和当前填写审阅的定义。顶栏切换继续保留该审阅定义与原文对照；浏览器后退、前进恢复各自的路由、原文焦点和阅读位置。

定义、字段、关联、入/出引用和文件列表按段查询。标量可继续查看全文，原文每段最多显示 120 行，长行可“继续本行”；预览和单个 4096 字符块不是完整值。别名子字段定位到原 anchor，原始 alias 行仍可查看。

每页独立持有视图、搜索、展开、分页、面板和滚动状态。共享审阅更新只局部更新输入、状态和计数，不替换整页。定义由文件路径、原始 SHA-256、section 和定义路径标识，重复业务 ID 不会合并；引用无匹配或有歧义时不猜目标。旧链接只有唯一匹配才转换，旧数据集或过期工作区链接明确报错；创建新工作区必须显式操作。

浏览器历史按条目保存本页的阅读状态：先恢复展开卡片和已加载分页，再恢复主区、目录及原文面板滚动；按原点击链接的相对位置补偿布局变化。`history.state` 只存不透明 ID，阅读状态留在本页内存；刷新页面或更换数据集后不恢复旧阅读状态。

## 审阅、冲突与导出

输入控件取得字段草稿租约后才可编辑。结论和备注分别进行字段版本比较并交换（CAS），每字段仅一个在途请求；持续输入和中文组合输入保留本地草稿。不同字段可独立提交，同字段冲突同时展示本地值与共享值，必须明确接受共享值或编辑合并后提交，不静默覆盖。

界面分别显示连接、同步、冲突、全局暂停和未导出状态。“已同步”仅表示工作区内存已确认，不表示保存到磁盘。

- **导入、清空、加载示例**影响所有接入页并重置审阅。先独立校验候选；解析失败保留当前模型与备注。候选就绪后暂停各页新输入，提交或拒绝既有草稿；全部应答后，由发起页最终确认最新审阅 R 与已确认保存 R。取消、冲突、失联或超时不能当作同意。
- **完整导出**短暂协调草稿屏障，截取同一数据集与修订号的不可变 v2 快照后立即解冻输入，再通过有界块组装完整 JSON 下载。
- 下载产生后点击**确认已保存**，并核实文件实际保存，才推进该快照的导出水位。下载期间的新编辑仍然尚未导出。可明确放弃待确认下载并释放句柄；不完整恢复副本不能清除 dirty。
- 失联时禁用共享提交，保留已收视图片段与本页草稿，可导出带“不完整 / 非权威”标记的恢复副本。重新接入不会把缓存提升为权威；未知提交结果保留为需要核对的冲突。

关闭/刷新会保守提示未确认草稿或未导出审阅，但强制退出、冻结、崩溃或系统回收不能保证提示和保全。关闭创建页不影响其他正常接入页；全部页面关闭、最后一页刷新、浏览器/worker 退出均不承诺恢复。服务重启或升级前请先导出，勿把内存工作区当作可靠存储。

## 检查覆盖与运行边界

M1–M6、ME 及可选 M7 / MU / MM / MI 的标准根列表进入索引。检查覆盖已登记的类型化引用、重复 ID、场景/流程局部 ID、事件生产与规则订阅镜像、部分 M6 约束及 M2/M7 配对。未知 Ref/Refs 和根键明确提示；支持字段以 `schema.js` 为准。

对象聚合只扩展相关行为、事件、规则、权限一跳，不是完整依赖闭包。生命周期仅展示声明；权限矩阵只列直接授予，不计算继承或 ABAC 的最终授权。不执行规则表达式、SQL、伪代码或接口调用，不提供模型编辑、全局图或语义 diff。本工具不替代 `omf_validate.py --strict` 或人工业务审计。

- 导入支持 UTF-8 块状 YAML 顶层映射、嵌套、多行文本与有界别名；拒绝重复映射键、多文档、自定义 tag、循环别名和 JSON/flow 顶层。
- 读取所选文件前先校验本批文件数、大小、扩展名及重复路径；核心另行校验合并后的上限。导入上限保持单文件 12 MiB、合计 40 MiB、最多 80 文件；每文件语法/展开节点各不超过 250,000，深度不超过 70。
- 通信限制针对在途/活跃资源：每端口最多 8 帧、512 KiB 未确认传输；每客户端默认最多 8 个未退休命令回执、1 MiB 回执签名窗口；同时最多 2 个候选和 4 个未释放下载。ACK、取消、保存确认或明确放弃释放资源，不按累计编辑、解析失败或导出次数耗尽会话。
- 列表最多 100 项、直接字段最多 50 项、源段最多 16 行、标量/长行块最多 4096 UTF-16 单位；响应超出 128 KiB 时缩小分页，不截断身份。完整导出块最多 16384 字符，不因已有合法模型的定义总数或整份 JSON 大小拒绝备份。
- 同时保留最多 32 个接入/待恢复身份及 48 个端口。显式 LEAVE 回收身份、候选和下载；新接入使用不同会话 nonce，旧会话或已退休序号不能重执行。没有心跳驱逐或自动屏障同意；不响应页面须取消、恢复或明确离开后再操作。
- 工具不使用 localStorage、IndexedDB、Service Worker 或业务 HTTP/WS 保存/传输模型。浏览器、操作系统和用户下载仍可能落盘；导出文件含备注、标识和指纹，应按项目保密要求保管。

## 维护与验证

只有维护源码、构建或测试才需要开发依赖。在本目录执行 `npm ci` 后运行：

```bash
npm test
npm run test:core
npm run test:runtime
npm run test:ui
```

`npm test` 包含核心/导航、DTO、真实 MessagePort/worker_threads、容量回收、服务/构建、干净分发及打包 HTML 的 DOM 回归。`shared-ui.test.mjs` 使用 **JSDOM + 真实 Node MessageChannel + worker_threads 宿主**，是多页替代集成，不是原生浏览器测试；它不能证明 SharedWorker、CSP、标签寿命、激活或下载行为。

构建必须完整顺序执行：

1. `node build.mjs start`，读取本次输出的 `parts`（不能硬编码数量）。
2. 逐个执行 `node build.mjs part 0` 至 `node build.mjs part N-1`，每片成功后继续。
3. `node build.mjs finish`，验证整套资源后发布版本目录、根 HTML 和清单，并维护 `.gitignore` 的当前版本例外；当前发布资源必须随源码/分发保存，历史版本保持忽略。
4. `npm test`，确认新产物。暂存与检查点在 `/tmp/omf-model-auditor-build-*`，完成前保留可用产物；不要并行写构建、跳片或混入变化的源码。

真实浏览器可复现入口为 `npm run test:browser`，需要已可用的 Playwright Chromium；也可显式设置 `OMF_CHROMIUM_EXECUTABLE`。脚本只使用 `/tmp` 下全新 profile、HOME、临时目录和下载位置，不读取用户 profile。它包含独立文件和本地共享服务流程、后退的真实滚动锚点、修饰链接、新页接入、关闭创建页及实际下载保存检查。

当前默认入口缺少 Playwright Chromium；显式指定宿主 Chrome 时，全新 `/tmp` profile 仍遇到宿主沙箱／ProcessSingleton 启动错误。不能据 DOM 通过宣布 macOS Chrome/Safari 验收。发布前仍须在获准环境验证真实滚动锚点、Cmd/中键/右键、后台冻结、最后一页刷新、全部页面关闭、IME、SharedWorker/CSP 和下载保存确认。不要接入私人 profile 或绕过安全策略。

内嵌 YAML 解析依赖为 yaml 2.8.1（ISC），许可保留在 HTML 内。esbuild、jsdom 和 Playwright 只用于构建/测试。使用审计器不改变 ontology-modeling 的业务建模阶段边界。
