# 可视化模型审计

本文件面向希望人工审查模型的程序员，以及需要交付审计入口的建模 agent。辅助工具只读展示已有 YAML，不生成业务实现、不修改导入文件，也不替代完整校验。

## 入口与使用顺序

- 工具入口：[离线审计器](../tools/model-auditor/omf-auditor.html)。单 HTML 可直接用浏览器打开，无需安装依赖或启动服务器。
- 完整操作与维护说明：[工具 README](../tools/model-auditor/README.md)。
- 在 skill 目录运行 `open tools/model-auditor/omf-auditor.html` 可在 macOS 打开工具。

1. 先按 `sync-and-validation.md` 运行完整结构校验。
2. 导入业务项目 `docs/model/yaml/` 中本次审查需要的全部模型。体验内置示例后，先清空工作区再导入真实模型，避免混入示例定义。
3. 按对象展开关联行为、规则、事件、权限；按 M4 场景和 M6 流程核查联动、人工活动与分支。需要核对时点击字段旁的原文行号。
4. 检查问题清单、引用关系与角色直接权限矩阵；未找到定义也可能是对应文件尚未导入。
5. 按当前定义填写人工结论与备注，导出 JSON 留档。导出记录带文件 SHA-256；修改模型后，应重新导入并复审受影响部分。

## 审计边界

- 只根据已登记的显式字段建立关联，不从名称或表达式猜测业务关系。检查支持范围以工具的 `schema.js`、`checks.js` 为准。
- 对象页展示直接关联及有限的一跳扩展，不是完整依赖闭包；M4/M6 按声明顺序展示，不推断执行拓扑。
- 生命周期仅显示状态；权限矩阵仅列直接授予，不计算最终授权。MVP 不含语义 diff、全局关系图或模型编辑。
- 数据仅存当前页面内存。刷新、关闭或成功重新导入会清空审阅记录；操作前先导出。导出 JSON 暂不支持重新导入恢复。
- 工具给出的零提示不代表业务正确；源 YAML 与建模资料仍须人工审查。
