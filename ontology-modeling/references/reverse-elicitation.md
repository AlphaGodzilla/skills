本文件是 `ontology-modeling` 的核心参考。它把成品模型（M1–M6，可选 M7/MU/MM/MI）反推成"必须由用户确认的事实"，再给出取证的中间产物与追问清单。用法：先读第一节，按模型逐行取证；对拿不到答案的项标 `待确认`，再按第二节追问；全部结果汇总进第四节的建模信息包。

## 一、反向信息需求表

读法：成品模型 → 该模型每个元素需要的事实 → 向用户提出的引导问题 → 事实缺失时漏掉什么。"缺失后果"列用于判断某个 `待确认` 能不能放过：后果是"漏模型"时必须在建模前闭环。

### M1 对象模型

| 模型元素 | 必须确认的事实 | 引导问题 | 缺失后果 |
| --- | --- | --- | --- |
| 聚合根 | 业务对象的业务身份是什么 | 这个对象用什么唯一标识？是系统编号还是业务编号？ | ID 设计返工 |
| 聚合根 | 它能否独立存在 | 这个对象在业务上会单独被查询、单独被修改吗？ | 边界错误，子实体被误当聚合根 |
| 生命周期 | 有哪几个状态、流转方向 | 这个对象一生经历哪几个状态？谁把它推进到下一格？ | 行为与流程无法落点 |
| 子实体 | 哪些明细与主对象同生共死 | 这些明细行能脱离主对象单独存在吗？删主对象时它们跟着删吗？ | 聚合边界错误 |
| 值对象 | 哪些是一组不可变特征 | 这组字段是整体替换、还是各自独立修改？ | 属性平铺，语义丢失 |
| 属性 | 每个字段的类型、必填、唯一、枚举、字典 | 这个字段必填吗？取值范围固定吗？业务数据要保存码值还是显示文本？ | 界面与落库口径漂移 |
| 属性规则 | 只依赖本属性的约束 | 金额必须大于 0 吗？名称有长度上限吗？ | 约束漏项或被错放进 M3 |
| 聚合不变性 | 依赖同一聚合多属性或子实体的规则 | 明细合计必须等于总额吗？开始日期不得晚于结束日期吗？ | 业务完整性失守 |
| 聚合关联 | 与其他独立对象的引用关系与基数 | 这个对象引用哪个对象？一个对多个还是多个对多个？ | 查询与流程缺连接 |
| 数据字典 | 哪些取值是受控码表 | 这个取值以后会不会增减？增减时要不要影响历史数据？ | 枚举硬编码 |

### M5 主体模型

| 模型元素 | 必须确认的事实 | 引导问题 | 缺失后果 |
| --- | --- | --- | --- |
| 参与者 | 谁在用系统、谁在系统外 | 直接操作系统的有哪些人、哪些系统？ | 角色与服务边界不清 |
| 外部实体 | 外部系统协议与契约 | 对接的外部系统用什么协议、什么认证、超时多久？ | 接口与集成设计返工 |
| 角色 | 职责分组与继承 | 这些用户分成哪几类职责？谁的能力覆盖谁？ | M6 人工活动无法落点 |
| 数据范围 | 每类操作看多少数据 | 这个角色能看全部、本部门还是只看自己？ | 越权或数据不可见 |
| 权限 | 哪个角色能做哪个行为 | 这个操作允许哪些角色执行？ | "按钮可见但行为被拒" |

### M3 规则模型

| 模型元素 | 必须确认的事实 | 引导问题 | 缺失后果 |
| --- | --- | --- | --- |
| 规则清单 | 哪些判断跨对象、跨行为或需复用 | 这条判断要读另一个对象的数据吗？会被多个功能复用吗？ | 规则散落在行为里 |
| 规则类型 | 验证、计算、推导、转换、风控中哪一类 | 这个判断是返回真假、返回一个值，还是评估风险等级？ | 规则无法归类 |
| 输入参数 | 从哪些字段或事件载荷取值 | 这条判断用到哪些字段？字段来自对象还是事件载荷？ | 规则无法执行 |
| 事件驱动规则 | 订阅哪个事件、满足后触发哪些行为 | 这件事发生后要先判断条件再决定下一步吗？条件是什么？ | 事件链断在中间 |
| 外部决策 | 是否委托外部规则引擎 | 这个判断由本系统算，还是由外部风控或信用系统给结论？ | 集成与接口遗漏 |

### M2 行为模型

| 模型元素 | 必须确认的事实 | 引导问题 | 缺失后果 |
| --- | --- | --- | --- |
| 行为清单 | 每个对象有哪些原子操作 | 这个对象能被执行哪些操作？每步只做一件事吗？ | 功能无法覆盖 |
| 行为类型 | 改状态、只读，还是事件处理器 | 这个操作会改变对象状态吗？还是只查询？ | 读写职责混用 |
| 触发方式 | 用户、系统、事件、外部接口 | 这个操作由用户点按钮触发，还是由定时、事件或外部接口触发？ | 事件链与接口漏挂 |
| 前置条件 | 执行前必须成立的状态 | 什么状态下这个操作才允许执行？ | 非法状态可执行 |
| 后置变更 | 执行后哪些字段变成什么 | 执行成功后哪些字段跟着变？ | 行为副作用不完整 |
| 规则调用 | 调用哪些 M3 规则 | 这个操作执行前要跑哪些判断？ | 规则成为孤儿 |
| 事件产出 | 成功后产生哪个事实事件 | 这个操作成功后，有没有别人需要知道"它做完了"？ | 事件链断裂 |
| 查询绑定 | 是否绑定一个 M7 查询报表对象 | 这个查询是单对象简单查询，还是要跨对象出报表？ | M7 一对一关系缺失 |

### ME 事件模型

| 模型元素 | 必须确认的事实 | 引导问题 | 缺失后果 |
| --- | --- | --- | --- |
| 事件清单 | 哪些"已发生的事实"需要被广播 | 这件事发生以后，还有谁或哪个对象需要跟着动？ | 跨对象协同丢失 |
| 生产者 | 每个事件唯一的生产行为或规则 | 这个事实是由哪个操作产生的？ | 事件来源不明 |
| 订阅者 | 谁消费事件，无条件还是有条件 | 下游是直接执行，还是要先判断条件？ | 事件链断尾 |
| 事件载荷 | 订阅者需要的字段 | 下游处理需要事件带上哪些数据，才不会回查数据库？ | 订阅者需回查，耦合加重 |
| 顺序语义 | 至少一次、恰好一次还是尽力而为 | 重复投递会造成重复记账或重复扣减吗？ | 幂等缺失，数据错乱 |

### M4 场景模型

| 模型元素 | 必须确认的事实 | 引导问题 | 缺失后果 |
| --- | --- | --- | --- |
| 场景清单 | 哪些是真实的跨对象事件协同 | 一个对象变化后，是否通过事件驱动了另一个独立对象变化？ | 场景漏建或虚构 |
| 源与目标对象 | 事件从哪个对象到哪个对象 | 这个事实的源头对象是哪个？最终改变的对象是哪个？ | 场景边界错误 |
| 场景步骤 | 行为、事件、规则的顺序 | 这条链是先执行行为、再发事件，还是中间要先判断条件？ | 语义链错误 |
| 场景边界 | 是否混入人工任务或网关 | 这条链里有审批人、角色任务或流程分支吗？ | M4 与 M6 职责混淆 |

### M6 流程模型

| 模型元素 | 必须确认的事实 | 引导问题 | 缺失后果 |
| --- | --- | --- | --- |
| 流程清单 | 哪些是端到端协同流、哪些是审批流 | 这个业务从开始到结束跨哪几个阶段？哪一段需要人工审批？ | 流程漏建 |
| 阶段 | 业务的阶段划分 | 这段业务分几个阶段，每个阶段的产出是什么？ | 流程结构错误 |
| 人工活动 | 每个任务的角色 | 这一步由哪个角色完成？ | 角色引用缺失 |
| 审批层级 | 按什么条件分级 | 金额、类型或组织不同时，审批层级怎么变？ | 审批流不完整 |
| 审批结果 | 通过、驳回、退回的走向 | 驳回后回到哪一步？退回后回到哪一步？有没有超时？ | 只有成功路径 |
| 网关分支 | 每个分支的条件与默认分支 | 这个判断分成几支？哪一支是默认？ | 分支不完整 |
| 子流程 | 协同流调用的审批流 | 这条主流程在哪一步调用哪条审批子流程？ | 流程重复定义 |
| 流程触发 | 手工、行为、事件、定时还是子流程 | 流程由用户发起，还是由某个行为、事件或定时任务启动？ | 触发器缺失 |

### M7 查询统计与报表模型（可选）

| 模型元素 | 必须确认的事实 | 引导问题 | 缺失后果 |
| --- | --- | --- | --- |
| 查询对象 | 哪些跨对象查询与报表 | 要跨哪些对象看列表、统计或导出？ | 查询无载体 |
| 对象类型 | 详情、列表、统计还是固定报表 | 这是查一条详情、查列表、做分组统计，还是固定格式报表？ | 类型选错 |
| 来源与关联 | 主对象与关联对象 | 主查哪个对象？关联哪些对象？怎么关联？ | 查询口径不清 |
| 参数与条件 | 输入参数、操作符、空值处理 | 用户按什么筛选？参数为空时是查全部还是跳过该条件？ | 查询结果不符预期 |
| 结果列与聚合 | 输出列、分组、合计 | 结果要哪些列？按什么分组？要不要小计合计？ | 报表口径错误 |
| 导出 | 导出格式 | 需要导出 Excel、CSV 还是 PDF？ | 导出缺项 |

### MU UI 模型（可选）

| 模型元素 | 必须确认的事实 | 引导问题 | 缺失后果 |
| --- | --- | --- | --- |
| 屏幕 | 有哪些界面、从哪进入 | 用户从哪个界面完成这些操作？界面之间怎么跳？ | 调用链无入口 |
| 元素 | 控件类型、输入输出、数据绑定 | 这个字段在界面上是输入框、下拉还是表格？绑定哪个对象属性？ | 绑定口径漂移 |
| 事件与调用链 | 每次操作触发什么 | 点这个按钮后依次发生什么：校验、调用行为、发事件、调场景、出报表、跳转？ | USER_ACTION 行为成孤儿 |
| 元素级权限 | 控件可见与可用 | 哪个权限控制这个按钮的可见或可用？ | "可见但被拒" |

### MM 对象-数据表映射模型（可选）

| 模型元素 | 必须确认的事实 | 引导问题 | 缺失后果 |
| --- | --- | --- | --- |
| 对象到表 | 每个持久化对象落哪张表 | 这个对象存在哪张表？复合对象拆成几张表？ | 落库映射缺失 |
| 属性到列 | 每个属性对应哪个列 | 这个属性对应哪个字段？值对象是前缀平铺还是存 JSON？ | ORM 与 SQL 错位 |
| 外键 | 表间外键与 M1 关联一致 | 主从表用哪个外键关联？ | 引用不一致 |

### MI 接口模型（可选）

| 模型元素 | 必须确认的事实 | 引导问题 | 缺失后果 |
| --- | --- | --- | --- |
| 接口清单 | 对外提供与依赖外部两类接口 | 本系统对外提供哪些接口？依赖外部哪些接口？ | 集成边界缺失 |
| 方向与分类 | 提供方、调用方、查询/命令/通知 | 谁调谁？这个接口只读、改状态，还是只发通知？ | 接口职责错误 |
| 输入输出 | 入参、出参、字段口径 | 每次交互输入什么、输出什么？字段与对象属性或报表列对齐吗？ | 联调口径不一致 |
| 返回规则 | 无记录、参数错误、空结果、失败 | 没有记录时返回什么？参数错误怎么返回？失败怎么处理？ | 异常约定缺失 |

## 二、场景补全追问清单

本清单用于第四步"挖场景"。对每个对象、每条功能逐类扫描；命中即记入场景清单，未命中也要在信息包中留一行"无"。括号内为对应模型落点。

### 1. 生命周期探测（M1、M2、M6）

- 这个对象一生有哪几个状态？请按顺序列出。
- 每个状态由谁或什么推进到下一格？是用户操作、定时任务还是外部事件？
- 有没有只能正向、不能回退的状态？
- 有没有"作废""归档""关闭"这类终态？进入终态时发生什么？

### 2. 跨对象联动探测（ME、M4）

这是最容易漏、也是本框架最核心的一类。逐条问：

- 这次操作完成后，是否还要新增、修改、删除或归档**另一个独立对象**？
- 是**无条件**执行（下游行为直接订阅事件），还是**有条件**（先由规则判断，满足后触发下游行为）？
- 被影响的对象与当前对象是不是同一个聚合？如果不是，就必须拆成事件链。
- 同一个事件是不是有多个下游（例如扣库存、发通知、启动评审）？
- 下游需要的字段，事件载荷里带了吗？

反例：合同提交后，直接改写开票对象的数据 —— 禁止，必须拆成"合同提交行为 → 合同已提交事件 → 开票归档行为"。
正例：合同废弃后归档开票与收款 —— "合同废弃行为 → 合同已废弃事件 → 开票归档行为、收款归档行为"。

### 3. 审批探测（M6、M5）

- 这个动作需要人工确认吗？
- 由哪个角色确认？有没有会签、加签？
- 按什么分级——金额、类型、组织、客户等级？请给出阈值。
- 审批通过后谁推进下一步？驳回回到哪一步？退回（退给发起人修改）回到哪一步？
- 审批有没有时限？超时是自动通过、自动驳回还是升级？

### 4. 异常路径探测（M2、M3、M6）

- 操作失败时对象停在什么状态？
- 允许重复提交吗？重复提交怎么识别？
- 两个人同时改同一条数据，谁赢？
- 支持撤销、红冲、反审核吗？撤销后要不要反向联动？
- 外部系统超时或返回失败时怎么处理？

### 5. 权限与数据范围探测（M5、MU）

- 这个操作允许哪些角色执行？哪些角色禁止执行？
- 每个角色能看全部数据、本部门数据还是只有自己创建的数据？
- 有没有按字段的可见性差异（例如金额只对财务可见）？
- 有没有外部参与方（客户、供应商、外部系统）直接操作？

### 6. 查询与报表探测（M7、M2）

- 有没有需要跨多个对象看的列表或详情？
- 有没有分组统计（按部门、按月份、按类型汇总）？
- 有没有固定格式报表，需要小计、合计、导出 Excel/CSV/PDF？
- 每个查询的筛选参数是什么？参数为空时查全部还是跳过该条件？
- 结果列的口径是什么（例如"未收款金额"怎么算）？

### 7. 外部接口探测（MI、M5、M2）

- 本系统对外提供哪些接口？给谁用？
- 本系统依赖哪些外部接口？调用时机是什么？
- 每次交互输入什么、输出什么？字段口径与哪个对象属性或报表列对齐？
- 无记录、参数错误、空结果集、失败时分别返回什么？
- 是同步请求响应，还是异步事件通知？

### 8. 界面入口探测（MU、M2）

- 用户从哪个界面发起这些操作？界面之间怎么跳转？
- 关键控件的输入输出是什么？绑定哪个对象属性？
- 点击按钮后依次发生什么：输入校验、调用行为、发事件、调场景、出报表、跳转？
- 有没有跨屏幕共享的行为（无操作超时、全局快捷键）？

### 9. 边界外探测（记录但不建模）

- 性能、容量、可用性指标：记录到非功能需求，不进九模型。
- 部署、运维、监控、灾备：记录到部署运维规范。
- BI 数仓、指标平台、自助分析：明确排除，不进 M7。
- 视觉样式、动画、主题：归设计系统，不进 MU。

## 三、提问轮次与格式

提问按依赖推进，一轮只问同一层。未定型的对象不进下一层问题。每批问题不超过 5 个：用户回答完当前批后，才生成下一批。

| 轮次 | 主题 | 前置 |
| --- | --- | --- |
| 第 1 轮 | 范围、领域边界、资料清单 | 无 |
| 第 2 轮 | 对象卡：身份、属性、生命周期、聚合边界 | 范围已定 |
| 第 3 轮 | 角色与数据范围 | 对象已定 |
| 第 4 轮 | 跨对象联动与审批（第二节的 2、3 类） | 对象与角色已定 |
| 第 5 轮 | 异常路径、查询报表、外部接口、界面入口 | 对象与行为已定 |
| 第 6 轮 | 信息包缺口复核 | 前五轮完成 |

分批规则：

1. 每批最多 5 题；同层问题不足 5 个也单独成批，不为凑数跨层提问。
2. 同批问题必须相互独立：任一题的答案不得是本批另一题的前提。
3. 问题编号跨批连续（Q1~Q5、Q6~Q10），便于引用与回溯。
4. 用户回答完当前批后才生成下一批；未回答不推进。
5. 用户要求"一次给完"时，仍按批编号并标注跨批依赖，未获答案的批次保持 `待确认`。
6. 需要查环境事实才能问的问题，先查证再并入合适批次，不塞进当前批。

格式要求：每题给编号与推荐答案，推荐答案必须可被直接采纳或否决。示例：

```
❓ Q7 - 合同提交后的跨对象联动: 合同提交成功后，除了改变合同状态，是否还要影响其他独立对象？

可选：A 仅改合同自身；B 同时启动审批流程；C 同时生成开票计划；D 其他

➡️ B。审批流程属于独立事务边界，应拆成"合同提交行为 → 合同已提交事件 → 启动审批流程行为"，不使用直接调用。
```

## 四、建模信息包结构

建模信息包是唯一事实源，任何模型字段都必须能追到信息包中的一行。全部信息包文件位于 `docs/model/intake/`，目录与内容：

```
docs/model/intake/
├── scope.md              # 范围卡：交付模型、领域边界、资料清单、边界外事项
├── glossary.md           # 名词表：名词 | 候选类型 | 定型结果 | 依据
├── ddd-extraction.md     # DDD 中间结果：领域事件表 | 领域模型表 | 事件-命令-模型汇总表 + M1~M6 取数索引
├── object-cards.md       # 对象卡：身份、属性、生命周期、子实体、引用、约束
├── scenario-list.md      # 场景清单：源对象 | 触发 | 目标对象 | 条件 | 下游 | 落点模型
├── actor-permission.md   # 角色权限表：角色 | 数据范围 | 可用行为 | 审批角色
├── flow-catalog.md       # 流程目录：阶段 | 角色 | 网关条件 | 驳回/退回/超时
└── open-questions.md     # 待确认清单：问题 | 影响模型 | 状态
```

状态标记只用三种：`已确认`（有用户明确答复）、`待确认`（尚未答复）、`边界外`（明确不建模）。禁止出现无标记条目。

对象卡模板：

```
对象: 合同
业务身份: contractId，业务编号 CN-YYYY-NNNN
聚合边界: 合同（根）+ 合同标的明细（子实体，同生共死）+ 付款条款（子实体）
生命周期: 草稿 → 已提交 → 审批中 → 已生效 → 已关闭 / 已终止
属性: contractNo(必填唯一)、contractName(必填, ≤100)、totalAmount(必填, >0)、status(枚举)
引用: customerId → 客户聚合；ownerId → 用户
局部约束: 到期日期不得早于生效日期（invariants）
跨对象联动: 提交 → 启动审批；关闭 → 归档开票与收款
```

## 五、信息包到模型的分发矩阵

产出模型时按此矩阵取数，避免同一事实在多处各写一遍。

| 信息包来源 | 主要落点 | 次要落点 |
| --- | --- | --- |
| 名词表 | M1 对象、属性、字典 | M5 角色、MI 接口 |
| 对象卡 | M1 聚合、子实体、值对象、约束 | M2 行为的 `ownerEntity` |
| 对象卡生命周期 | M2 行为的前后置条件 | M6 流程阶段 |
| 场景清单（无条件） | ME 事件 + 事件订阅行为 | M4 场景（跨对象时） |
| 场景清单（有条件） | M3 事件驱动规则 | ME 订阅者、M4 规则步骤 |
| 角色权限表 | M5 角色、权限、数据范围 | M6 `roleRefs`、MU `permissionRef` |
| 流程目录 | M6 流程、活动、网关 | ME 事件触发、M4 场景调用 |
| 查询报表需求 | M7 查询对象 | M2 `QUERY` 行为一对一绑定 |
| 界面入口 | MU 屏幕、元素、调用链 | M1 `uiBindings`、M6 `screenRef` |
| 外部接口需求 | MI 接口契约 | M5 `ExternalEntity`、M2 `EXTERNAL` 行为 |
| 限界上下文 | 模块、包或文件拆分依据 | MI 接口边界、M4 跨上下文协同、M6 流程阶段 |
| 边界外事项 | 不落地 | 记入非功能需求或实现规格 |
